## 项目简介

《UE5DroneControl》是一个基于 Unreal Engine 5.7 搭建的数字孪生无人机控制平台。它不是只在引擎里展示无人机模型，而是把 UE5 客户端、C++ 后端、Jetson 机载桥接服务和 PX4 飞控连接成一条双向链路：真实无人机的遥测状态会回到虚拟场景，用户也可以从 UE5 发起控制或阵列任务，经后端和 Jetson 下发到物理设备。

平台支持实时遥测、无人机状态管理、目标点控制、航点编辑、阵列任务预演与下发、Cesium 地理场景、影子机 / 镜像机显示，以及视频流和延迟测试等功能。项目的难点不在某个单独界面，而在于让不同设备、不同进程和不同坐标系中的状态能够被可靠地解释、传输和验证。

## 三端架构：从虚拟场景到真实飞控

```
UE5 客户端（交互 / Cesium / 镜像机 / 影子机）
              ↕ HTTP / WebSocket
C++ 后端（状态 / 队列 / 任务 / 坐标转换）
              ↕ UDP 控制与遥测
Jetson 机载桥接（协议校验 / 去重 / setpoint 缓存）
              ↕ ROS2 / Offboard
PX4 飞控与无人机
```

三端各自承担不同职责：UE5 负责交互和世界坐标，后端负责业务状态、任务调度和协议转换，Jetson 负责机载侧的协议终点与持续发送 Offboard setpoint，PX4 负责飞控执行和安全状态。这样的拆分让虚拟场景、网络服务和飞控逻辑可以分别测试，也让问题能够被定位到具体链路。

## 跑通 OODA：把虚拟系统接回物理现场

我曾前往外场与硬件工程师对接测试，并跑通了这套系统的 OODA 循环：

1. **Observe / 观察**：物理侧采集无人机的位置、姿态、电量等状态，经 Jetson 和后端回传；
2. **Orient / 判断**：更新 UE5 中的数字孪生状态、GPS 锚点和场景位置，形成对当前态势的理解；
3. **Decide / 决策**：在虚拟场景中进行目标点控制或任务 / 航线推演，生成控制或调度指令；
4. **Act / 行动**：指令经过后端和 Jetson 的校验与转发，由 PX4 执行，并产生下一轮观测。

这个闭环也对应项目中的 Real2Sim2Real 工作方式：同一套场景、坐标和任务资产既用于运行期的控制反馈，也用于开发期的仿真、联调和现场验证。
